description: Clarify an ML objective and choose the smallest useful experiment
---
Read the project brief, protocol, checkpoint, project limits, and linked run or
external records. Identify the requested deliverables, prediction unit, data,
metric/direction, acceptance constraints, authorization state, baseline, validation
stage, and evidence required to call each item complete. Mark unspecified success
thresholds unknown instead of inventing them. Ask focused questions about
consequential gaps while continuing independent inspection.

Create or refresh protocol.md before substantial experimentation with:

- an acceptance-status matrix using delivered, verified, pending, blocked, not
  requested, or unknown;
- prediction-time assumptions and a relevant train-to-inference contract covering
  schema, missingness, entity coverage, learned-transform fit scope, auxiliary-join
  cardinality/availability, and output alignment;
- split rationale, actual data/split identity, prior exposure, immutable reference
  baseline, and confirmation design;
- a consolidated ledger separating candidates, fits, failed infrastructure
  attempts, runtime, confirmation accesses, remote jobs, submissions, and remaining
  capacity;
- a protected closure reserve for final fit or reproduction, artifact checks,
  authorized external receipts, checkpointing, and the user report;
- the next falsifiable question, parent/reference run, one coherent changed factor,
  cheapest useful test, expected mechanism, acceptance and rejection gates,
  uncertainty plan when a close result would affect promotion, stopping condition,
  and reversal evidence.

If resuming, use attempt time, source revision, run IDs, and external IDs to exclude
later current-only state from earlier conclusions. Reconcile prior searches and
promised validation work before proposing more configurations. Once a confirmation
score has been observed, label it adaptive for later decisions and establish a new
untouched design before promising fresh confirmation. Prefer saved-prediction
ablations over refitting when mathematically sufficient.

Before expensive work, plan a preflight for interpreter/test runner, dependencies,
project-relative sources, authorized credentials, and a smoke test. For remote work,
plan registration, short bounded polls, durable handoff, terminal output import,
and receipt verification rather than one blocking wait. Update the brief with
confirmed decisions, save a checkpoint, and establish a baseline quickly instead
of extending planning. Candidate allowances are ceilings, not targets, and a plan
is not authorization for an external action.
$@

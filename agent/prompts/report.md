---
description: Write a concise report from the project's evidence
---
Write a report in reports/ from immutable project evidence. Start with an
acceptance-status matrix listing each requested deliverable as delivered, verified,
pending, blocked, not requested, or unknown. Do not mark the task completed while
a required item is pending or blocked, and do not invent a missing numeric success
threshold.

Include:

- objective, prediction unit/horizon, official metric and direction, agreed gates,
  authorization state, and exact dataset/split identity;
- the retained reference baseline and all comparable executed candidates, with run
  IDs, source revisions, resolved configs, changed factors, candidate exposure,
  fit/runtime cost, status, and accept/reject decisions;
- train-to-inference contract checks for relevant schema, missingness, fit scope,
  joins, feature availability, IDs/order, coverage, and prediction semantics;
- development ranking separately from exposed/adaptive and untouched confirmation;
- paired deltas, fold/origin variability, defensible uncertainty, promotion rule,
  and diagnostic slices when a close difference affected selection;
- observed error patterns separately from causes, alternative explanations, losing
  results, and evidence that would reverse the conclusion;
- external actions linked to source revision, selected run, artifact SHA-256,
  schema validation, command result, server-side ID/listing, terminal status,
  score/rank when available, and observation time;
- failures and warnings, including the original signature, root-cause hypothesis,
  minimal patch, and targeted regression check when resolution is claimed;
- the final selected config, exact reproduction command, artifact location and
  digest, total resource ledger, remaining budget, limitations, blockers, and next
  resumable action.

Review the chosen run with godel_review. Execute and validate the selected final
path when authorized and feasible, checking row count, headers, unique IDs/order,
finite values, and task-specific bounds or probability normalization. A successful
process, push, upload, local test, or valid number alone is not terminal training,
accepted submission, leaderboard scoring, deployment, or behavioral improvement.
If remote work remains active, report the immutable job/version, run ID, last
status/time, next bounded poll or collection command, and recovery instructions.
Link exact commands and save a timestamped checkpoint with attempt/session and
source revision when finished.
$@
